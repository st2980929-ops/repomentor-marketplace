# Knowledge Assessment

四列独立记录，不能被单一「已完成」覆盖：

| 维度 | 通过证据 |
| --- | --- |
| 已学习 | 实际讨论/阅读的主题及日期，仅表示接触 |
| L1 已理解 | 用户自己的解释：问题、原理、数据流、取舍，并正确回答一个边界/反例 |
| L2 已独立实现 | 用户代码路径/版本、独立程度、基本测试实测、真实排错记录或明确标注的故障诊断题、关键代码解释；代写或照抄不算独立 |
| L3 迁移通过 | 新场景/改变约束的题目、用户设计/代码与实测、适用边界；重复原题不算 |

仅换样例值、字符、payload 或重复执行同一算法不能作为 L3。迁移题需改变使用场景、接口约束、故障策略或设计，并要求学习者说明如何调整。微任务可以把尚未到时机的 L3 留为未验证，在阶段迁移题中补证据，不能为凑齐列而降低标准。

各列独立状态：`未验证`、`通过`、`未通过`。每次事件附日期、任务 ID、要求、用户实际回答摘要/代码版本、依据、证据位置，不能由 L2 自动推断 L1/L3。

保留历史失败及旧版本，新修复事件链接旧失败。证据冲突、通过后改代码或来源不明时待复核，先比较差异；不能抹掉旧失败或误报为新版失败。

每阶段记录已通过/未通过/未验证、盲区与复习。默认满足该阶段三级标准才达标。用户明确跳过则允许继续，记对象、请求摘要及未验证，阶段为「流程完成，掌握未验证」，不得计为已掌握。

没有运行结果写「已编写未运行」；缺依赖为未满足前置，场景未发生为条件未触发，范围外和用户搁置单列。量化须有分母、标准、证据和限制；否则逐项报告。
