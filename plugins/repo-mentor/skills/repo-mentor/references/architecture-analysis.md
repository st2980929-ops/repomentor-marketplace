# Architecture Reverse Engineering

选一条与学习目标有关的真实输入路径追踪至输出，再覆盖异常分支和状态变更。关键边附调用点、类型或测试证据。

记录实际存在的入口、业务、API、持久化、配置、集成和测试；库项目可能没有 HTTP 或数据库，不套分层。标注未读模块及抽样范围。

核心链：输入来源/格式 → 校验/转换 → 模块调用 → 状态位置/生命周期 → 错误传播或恢复 → 输出。只分析实际机制：数据结构、算法、接口、并发、缓存、权限等；缺证据就标未发现，不补造模块。

决策条目：

- **事实 F-n**：固定 SHA、`path:line`、类/函数，说明做什么；远程用固定 SHA 的 blob 链接。
- **推断 I-n**：可能动机、支持的 F-n、其他合理解释。没有设计文档不能说是作者自述。
- **假设 H-n**：不确定结论及需要读取/验证的内容。
- **取舍**：替代方案、优缺点、何种需求/负载下应改变；区分教学简化与生产约束。

用 `assets/architecture-template.md` 产出 `.learning/ARCHITECTURE.md`。有帮助时加 Mermaid，并映射实际模块。静态阅读测试证明测试存在及其意图，不能证明当前环境通过。
