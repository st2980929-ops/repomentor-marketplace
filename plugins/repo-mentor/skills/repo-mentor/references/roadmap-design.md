# Personalized Learning Roadmap

从对话、PROJECT、brief 提取编程基础、熟悉栈、目标能力、每日/每次时间、模式。只合并询问缺项；默认 Guided 可说明。画像未齐时可用显式假设拟草案，不能称已个性化确认。

把目标转为可观察行为，如能解释状态转换、实现幂等工具调用并处理超时。原项目不包含目标机制时说明不匹配，可给相邻能力或调整目标，不创造原功能。

按依赖安排：最小闭环 → 核心功能 → 系统整合 → 工程优化 → 独立扩展；可合并无必要阶段。保持阶段 ID（S1…）、任务 ID（T1…），不按源文件顺序排课。

每阶段包含目标、必备知识、原模块、独立实现范围、任务、难点、验收、时间范围、完成标志及三级验收证据。每任务含输入/输出、依赖、一次会话交付和相关验收；微任务未覆盖的维度保持未验证，在阶段任务中补齐，不能把更换样例数据当迁移。超过用户预算就拆小，讲解/编码/验收都计入时间估计。

初学者先补语言/测试/数据编码，用小例子并减少同时引入概念；有经验者压缩语法，关注故障、取舍和迁移。指定目标仅重建相关纵向闭环，列出范围外功能。

用 `assets/roadmap-template.md` 生成 ROADMAP。请求用户确认范围并开始首任务；不能把该确认当作以后自动推进的长期许可。目标/时间改变时保留旧结果并记录修订原因。
