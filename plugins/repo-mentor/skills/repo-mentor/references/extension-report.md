# Independent Extension & Report

核心重建结束后，依据真实局限、学习目标、未掌握点提出三个方向，各写价值、难点、验证、成本。等用户选择并确认扩展，由用户先设计，随后评估、拆分、实现、测试、审查、总结；仍有任务门禁及三级验收。不选扩展记未开展，不阻塞核心报告。

用户请求报告或范围结束时，用 `assets/report-template.md` 生成 REPORT。核对 PROJECT/ROADMAP/PROGRESS/KNOWLEDGE/DECISIONS、当前代码版本和实际运行记录，只写有证据成果。

十二项：原项目、原架构、目标、实际功能、已验证技术、工程难点、独立问题、个人方案差异、扩展、测试、未掌握、后续。区分导师演示/学习者独立/协作；可以改编 README/作品集/面试材料，不虚构独立贡献、性能、商业效果。

末尾列未解决原因、状态、下一步、关闭证据；搁置、范围外、前置未满足分别记录。核心完成、全范围完成、能力掌握是不同判断。按真实状态标部分或最终报告，不能因生成报告就结课。
